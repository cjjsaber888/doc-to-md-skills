# 输出示例：quota-pdf-to-calc-kb

一个子目被解析成一条机读记录，同时发射为可读 Markdown。以下内容均为虚构示例，用于展示结构。

## 第一层 `quota_data.json` 中的单条记录

```json
{
  "code": "1-1-3",
  "name": "人工挖沟槽土方",
  "unit": "100m³",
  "chapter": "1",
  "labor": [
    { "name": "人工", "unit": "工日", "qty": 2.5, "price": 106.28, "amount": 265.70 }
  ],
  "material": [
    { "name": "水", "unit": "m³", "qty": 0.3, "price": 3.0, "amount": 0.90 }
  ],
  "machine": [
    { "name": "机动翻斗车", "unit": "台班", "qty": 0.25, "price": 480.0, "amount": 120.00 }
  ],
  "amount_items": [],
  "base_price": 386.60,
  "verify": {
    "computed": 386.60,
    "delta": 0.0,
    "status": "pass"
  },
  "notes": ["本定额按干土编制，如挖湿土，人工乘以系数 1.18。", "沟槽深度超过 4 米时，按相应定额子目乘以系数 1.15。"],
  "source": { "table": "1-1-3", "page": 12 }
}
```

## 基价闭环校验

```
基价 = 人工 × 人工单价(106.28) + Σ材料 × 材料单价 + Σ台班 × 台班单价 + Σ金额项
     = 2.500 × 106.28 + 0.300 × 3.00 + 0.250 × 480.00
     = 265.70 + 0.90 + 120.00
     = 386.60

原文基价 386.60    计算值 386.60    偏差 0.00    通过
```

闭环是硬闸。若计算值与原文不符，说明提取有错位，必须回源页查，不允许改数字凑通过。

## 第二层 `02-定额数据层/第01章-土方工程.md` 片段


## 第三层 `03-套用规则层.md` 片段

```markdown
# 套用规则

## 表 1-1-3 人工挖沟槽土方

- 基准条件：干土，沟槽深度 ≤ 4 米
- 调整 1：挖湿土，人工系数 × 1.18
- 调整 2：沟槽深度 > 4 米，子目系数 × 1.15
- 单位换算：定额单位为 100m³，实际工程量按 m³ 计量时先除以 100
- 冲突处理：两条调整同时成立时先乘人工系数，再乘子目系数
```

## 这个例子想说明什么

普通 PDF 转 Markdown 得到的是「一堆能读的字」。这个技能得到的是三种东西：机器可直接套用的结构化记录、人能快速核对的表格、以及一条能自我验证的闭环算式。第三样是关键，它让「提取是否正确」变成一个可运算的问题，而不是靠人逐个数字比对。
