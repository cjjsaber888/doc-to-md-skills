# 图文混排 PDF → 条目化知识库 + 单文件站点

## 一、能力边界

| 能做 | 不能做 |
| --- | --- |
| 图文混排 PDF 的文字抽取与章节切分 | 图片内容的语义识别（图里写了什么看不出来） |
| 整页影印保版面，案例图与页号一一对应 | 矢量重排或图片美化 |
| 断语/规则条目化，带部位、判词、原文摘录、出处页、置信度 | 判断源文档内容是否正确 |
| 单文件 HTML 站点（离线可用、全文检索、类型筛选、灯箱） | 在线部署（需另用发布技能） |
| 结构化输出 JSON / CSV，供 RAG 或 Excel 用 | 替代原书阅读 |

## 三、⚠️ 图像层有三层去重陷阱，必须逐层处理

图册型 PDF 的"图片总数"是三个不同口径，混淆任意一层都会让图号与照片错配。

| 层 | 口径 | 判别方法 | 实测（85 页相术案例册） |
| --- | --- | --- | --- |
| 第一层 | `page.get_images(full=True)` 报的引用数 | 同一图被挂到多页资源字典，每页都报一次 | 256 次引用 |
| 第二层 | 版面实际绘制矩形 `page.get_image_rects(xref)` | **同一页内可能把同一张照片画两遍**（矩形完全相同） | 270 处绘制，去重后 256 |
| 第三层 | 图像内容哈希 MD5 | **跨页复用的对象 xref 不同、内容完全一致** | 256 张实为 93 种图像 |

```python
# 第二层：同页按矩形去重（否则标注框会出现"幽灵框"）
seen=set(); items=[]
for it in rec['items']:
    k=tuple(round(v,1) for v in it['rect'])
    if k in seen: continue
    seen.add(k); items.append(it)

# 第三层：按内容哈希归并（遍历全部 xref 建 xref→md5 映射，再按案例图回查）
h2x={}
for x in range(1, d.xref_length()):
    try: info=d.extract_image(x)
    except Exception: continue
    if info.get('image'): h2x[x]=hashlib.md5(info['image']).hexdigest()
```

**为什么第三层是必做项**：跨页复用的照片会被作者挂到**不同的判定结论**下。实测最严重的一张照片出现在 9 个页面、跨 4 个章节板块，同一张脸既当"父亲先亡"的案例，又当"兄弟关""婚姻关""职业关三迟命"的案例。
不查出这件事，"图文互证"就是假的——读者会以为每张图是某条断语的专属证据。
查出之后，必须在图注下方显式标注「同源复用：另见 Pxx、Pyy / 所跨案例组：… / 该图不可单独作为某条断语的独立佐证」。

交叉验证技巧：**哈希结果要与视觉描述对读**。若哈希判定 P9-1 与 P77-1 同源，而两次看图都描述成"花白胡须老年男性"，则两条独立证据互证，结论可写死；若描述明显不同，说明哈希撞了或矩形切错，必须回查。

## 四、⚠️ 版面图与单张图要各留一套

不要二选一，两套都要，各自解决不同问题：

| 产物 | 生成方式 | 用途 |
| --- | --- | --- |
| 整页影印 `images/pageNNN.jpg` | `page.get_pixmap(Matrix(1.6,1.6))` | 保版面，读者核对原书版式 |
| 单张裁切 `images/case/pNNN_MM.jpg` | `page.get_pixmap(clip=rect, matrix=Matrix(4.2,4.2))` | 逐图成卡，图注与照片一一对应 |
| 编号标注页 `images/annot/pageNNN.jpg` | PIL 在整页影印上画红框 + 白字编号 | **喂给视觉模型读图用**，编号与裁切件文件名严格对应 |

编号标注页用 PIL 自己画，不要用 MCP 的 `draw_bbox`：前者能控制字号、徽标底色、逐张循环，48 页一次跑完；后者一页一次调用，且字体不可控。

```

## 五、章节切分原则

不要按页码均分，按源文的**标记句**切。这类资料有稳定的段落标记：

| 标记形态 | 含义 |
| --- | --- |
| `XX关`、`二.其他相法`、`XX歌诀` | 章/节标题 |
| `以上是……`、`以下都是……` | 案例图段的收尾标注，本身就是条目 |
| `重点；`、`用法：` | 作者自标的要点 |
| 韵文（分号连缀、字数齐整） | 口诀，单独成条 |

「以上是……」类句子是宝藏：它把"案例图属于哪一类"这件事写死了，直接做成 `案例标注` 类型条目，站点里就能实现"断语↔案例图"互跳。

条目 schema（断语）：

```

条目 schema（逐图描述，`case_desc*.json`）：

```json
{"page": 9, "no": 1, "file": "images/case/p009_01.jpg",
 "obj": "面相",                          // 手相 / 面相 / 图示
 "who": "老年男性，花白胡须，正面照",     // 只写可见主体特征
 "feat": ["额部多道深横纹", "眉毛浓黑", "法令纹深"],
 "note": "须白、额纹深，父亲先亡组样本之一",
 "rel": ["FM-01", "FM-07"]}              // 手工关联的断语编号
```

生成器要点（参考实现见 `../手面相江湖铁断-知识库/build/generate.py`）：
1. 章节表 `CHAPTERS` 手写，含序号、章名、部类、源页、一句话定位；**案例图与章的归档由源页区间自动推导**，别手写图页列表（改页就会漏）。
2. 断言每个章名都有条目（`assert name in {e['chapter'] ...}`），防止改数据时章名写错导致整章静默丢失。
3. `load_cases()` 要兼容多种 desc 文件结构（平铺 `items` 与 `batches` 嵌套都读），否则新增批次文件就崩。
4. 站点把数据 `json.dumps(..., ensure_ascii=False, separators=(",",":"))` 内联进 `const DATA={...}`，并把 `<` 转成 `\u003c` 防破格；离线可用、零外部依赖。
5. 检索覆盖 `id/ch/topic/pn/rule/quote/kind/page/rel`（图注视图中再加 `obj/who/note/group/feat/图号`），图号支持输 `P24-3`。
6. 图片路径统一 `../images/...`（`docs/` 与 `site/` 都是同级目录，相对路径一致）。
7. 卡片图用 `aspect-ratio:3/4; object-fit:contain`：面相竖图与手相横图混排时不会被裁掉。

## 七、视觉逐图描述流水线（本技能的核心增值）

视觉工具（`read_image` 之类）是**把图片回传给当前模型**，不是返回一段文字描述。所以流程是"我读图 → 我写图注 → 落盘"，不是调一个 API 就拿到文案。

**做法**：按页读「编号标注页」，一次读一页、当场把这页每张图的描述写进 `case_desc*.json`。**不要**一张一张读裁切件（本例 256 张，读不完）。

| 步骤 | 动作 |
| --- | --- |
| 1 | 生成 `images/annot/pageNNN.jpg`（整页影印 + 红框 + 编号） |
| 2 | 逐页 `read_image`，每 3—6 页落盘一次（防上下文丢失，可断点续跑） |
| 3 | 按编号顺序写出每张图的 `obj / who / feat / note / rel` |
| 4 | 描述直接对照**本书自身的判据体系**选特征，不要泛泛写"面相不错" |

**图注写法**（决定可用性）：
- `who` 只写可见主体特征：性别、年龄段区间、发型、衣着色、视角（正面/侧脸/手背/掌心）。**不推断身份、不写年龄确值、不写健康状况。**
- `feat` 按原书判据选：本例用「额横纹数、法令、奸门、眉浓淡、耳廓反、拇指骨肉、指腹饱满度」，因为书中断语就是拿这些作判据。**特征与断语共用词汇表**，读者才能对照。
- `note` 一句话点出这张图在书中承担什么角色（"父亲先亡组样本""唯一侧脸样本，专看耳廓"）。
- 示意图（`obj=图示`）：记录**图上的标注文字**与用途，例如"标注「眉是手」「法令是脚」「鼻是阴茎」"，而不是描述线条。
- 描述里发现的问题要写回校勘页：如"同一照片在 P25 标一生无子女、在 P39 标一生光棍"。

工具选择：批量读图可一次发多个 `read_image` 调用；页内文字多、图小的页面用 `budget:"small"` 省上下文，图多需细看时用 `"normal"`。

## 八、图文双向绑定（"相辅相成"的落点）

单向链接不够，必须双向可查，否则读者在断语表里看不到图、在图鉴里看不到结论。

1. **手工 rel**：写图注时把该图真正支撑的断语编号填进 `rel`（如手相拇指样本 → `ZFM-01/ZFM-02`）。
2. **自动绑定**：`案例标注` 类条目的 `part_name` 里本来就带页码区间（如"面相照片（P8—P10）"），用正则抽出页码，把该页全部案例图自动挂到这条断语下。

```python
def _pages_in_text(t):
    ps=set()
    for m in re.finditer(r'P(\d+)(?:\s*[-—]\s*P?(\d+))?', t):
        a=int(m.group(1)); b=int(m.group(2)) if m.group(2) else a
        if 1<=a<=85 and 1<=b<=85: ps |= set(range(a,b+1))
    return ps
```

实测效果：只做手工绑定覆盖率 57/213；加上自动绑定后**全部 256 张图都至少被一条断语引用**，反向无孤立图。

3. **复用警示必须显示在图卡上**，不能只写在数据里——读者看图时就要知道"这张图不是专属证据"。

## 九、置信度门控（不编造原则）

| 分值 | 含义 | 处理 |
| --- | --- | --- |
| 0.95 | 源文明确直述 | 正常 |
| 0.90 | 源文直述，需上下文补足 | 正常 |
| 0.85 | 表述含歧义 / 依赖原书图示 | 标待核实 |
| 0.70 | 疑似讹字、阙文、序列不可确证 | 标待核实 + 写入校勘页 |

源文没有的数字、方位、序号一律不补，用 `[需核实:字段]` 占位。
方位序列类（八卦、地支、九宫）若原书靠图传达而文本层只剩散排字，**照录原文阅读顺序 + 置信度 0.7**，不要自作聪明还原成"标准"方位。

## 十、知识库建成之后：可推断性评估（用户常追问的一步）

知识库建好≠能按书推断。当用户问"给你一张照片你能推断吗"，不要凭感觉答，做三步实测并把结论写进文档。

### 10.1 第一步：按输入通道给全部条目分类

把每条的 `part_name` 映射到它需要的输入通道（可多选）：面相 / 手相 / 触诊（摸、推、按）/ 动态观察（走相、声音）/ 气色。再按子通道细分（需侧位、需宫位定位、需流年定位、需年代校正）。

产出的关键数字是**「纯单一通道条目数 ÷ 总条目数」**。实测相术案例册：213 条中纯手相只有 13 条（6.1%），面相宽口径 154 条（72.3%），两者交集为 0，合计只覆盖 167 条——**不要把手相与面相相加当总数**。

### 10.2 第二步：用原书自带的标注案例做盲测

图册类资料常有"以上 N 张是××"的标注，这等于自带标准答案，是唯一可用的校准集。做法：

1. 按标注句确定分组边界（注意：标注句常位于某页第 k 张之后，边界要按张数切，不是按页切）。
2. 把逐图描述里的特征编码成离散候选特征（显式字典，键=特征名，值=关键词列表；**不要用变量代替字面量**，否则会出现全部 100% 的荒谬结果）。
3. 逐特征算两组出现率与差值。
4. **门槛取「25% 与 2 倍标准误」的较大者**——小样本下这一步不能省。

```python
import math
p1, p2 = a/na, b/nb
se  = 100 * math.sqrt(p1*(1-p1)/na + p2*(1-p2)/nb)
thr = max(25.0, 2*se)          # 判据
usable = abs(100*p1 - 100*p2) >= thr
```

实测教训：n=12/14 时 2 倍标准误中位数达 24.6 个百分点，**噪声下限高于 25% 的经验门槛**。首次只按 25% 判定时，某特征以 -29% 越线被判"可用"，补正后为 -12%、门槛 ±35%，判定不可用。少了这一步会把噪声当发现。

### 10.3 第三步：把三类混淆写清楚

| 混淆 | 检查方法 | 实测表现 |
| --- | --- | --- |
| 年龄代理 | 统计样本中明显老年（老年/秃顶/白发/灰发）的占比 | 81%，额横纹/法令深/面颊下垂在老年面孔上近乎人人具备，两组都亮 |
| 特征不可捕获 | 数条目里含量化表述的比例 | 纯静态 102 条中仅 10 条有量化判据，其余是整体性"好/不好"判断 |
| 样本复用污染 | 按内容 MD5 查该组照片是否被其他案例组引用 | 27 张中 22 张另被用于 5—9 个案例组，独立性不成立 |

结论写法要区分档位：**「系统性分离但方向相反」（手相，仍有信息）≠「无判别力」（面相，可能是样本量不足）**。样本量不够时只能写"本节无法得出比无判别力更弱的结论"，不能反过来说"证明无效"。

### 10.4 顺带挖出的真问题

盲测常会顺带暴露源文档自身矛盾，这比评估结论更有价值：
- 规则文字与案例标注方向相反（21 张手相案例：书中规则说骨多→奶先亡，实测两组恰好反过来）；
- 标注张数与可辨张数不符（书中称 15 张，实推 12／14）；
- 同一张照片支撑互相独立的结论（P25 标"一生无子女"、P39 标"一生光棍"）。

这些都要写成"两种解释都无法排除"，而不是替源文档下判断。

### 10.5 最后一步：给出可量测性判断，而不只是"不能"

不要停在"不能推断"。逐条对照书中表述，看它能否转成可自动量测的指标：
"男左女右看两边、那边不好那边先亡" → 中线偏移、两口角高度差、两耳上缘高度差；
"三停定应期" → 三停高度比。
能转的是可做的部分，转不了的（需触觉的骨肉比、需活体观察的走相声音）才是真缺口。

## 十一、让知识库"可推断"：三层资产（用户最终往往要的是这个）

评估只能回答"能不能"，用户真正的目标是"能按书判断"。做到这一步需要三件资产，缺一不可：

| 资产 | 作用 | 交付形态 |
| --- | --- | --- |
| 观测槽位表 | 把判定依据拆成可逐项填写的槽位 | `infer/slots.json` |
| 判定引擎 | 槽位 → 书中断语命中，确定性可重放 | `build/engine.py` + `infer/rules.json` |
| 采集引导页 | 让用户拍出能填表的照片 | `capture/index.html`（本地 `getUserMedia`） |

### 11.1 铁律：观测层与判定层必须分开

| 层 | 谁做 | 性质 | 可审计性 |
| --- | --- | --- | --- |
| 观测层：照片 → 槽位取值 | 视觉模型或人工 | 概率性，会看错 | 可复核：每个槽位都是枚举/计数 |
| 判定层：槽位 → 断语命中 | 引擎（纯确定性） | 可重放 | 命中必附命中条件与依据槽位 |

**绝不要让模型直接给结论**。混在一起就无法区分"看错了"与"书里就是这么写的"，用户无法复核，也无法定位错误来源。

### 11.2 槽位表设计

- 槽位键用 `域.名称`（`hand.*` / `face.*` / `meta.*`），引擎只读表内定义的槽位，不读自由文本。
- 每个槽位带：`type`（enum/count/bool/list）、`values`、`view`（所需拍摄角度）、可选 `touch`/`map`/`color` 标记。
- `touch`/`map`/`color` 三个标记至关重要：它们让引擎能把"不可判"细分为"源文要求触摸""需定位图""需受控拍摄"，而不是笼统地说"没填"。
- 规模参考：相术案例册做了 84 个槽位（手相 27 / 面相 54 / 元数据 3）。

### 11.3 规则表与三态输出

规则形如 `{entry, slots, branches:[{when:[{slot,op,value}], say}]}`，`op` 支持 `== != in has has_any has_none >=`。引擎输出三态：

| 态 | 条件 | 必须附带 |
| --- | --- | --- |
| 命中 | 槽位齐备且某分支匹配 | 命中条件文字 + 依据槽位取值 + 条目置信度 |
| 未命中 | 槽位齐备但无分支匹配 | 说明"槽位齐备但不满足条件" |
| 不可判 | 槽位缺失/性别不符 | 缺失槽位清单 + 原因（未采集／未填／结构性不可判／性别限定） |

配套两条硬规则：
1. **不做优先级裁决**。同一槽位命中多条时列出冲突清单，让用户自己看，绝不自行加权择优。
2. **第三方闸门**。若断语指向不在场的第三方（父母/配偶/子女），默认隐藏，须显式开关才输出。

**不可判四分类**尤其有用，它把"知识库的缺陷"和"本次没拍"分开：`not_collected`（本次未采集该通道）、`slot_missing`（拍了没填，补填即可判）、`blocked`（现有通道无法支撑）、`gender`（性别限定）。用户看到分类就知道下一步该干什么。

### 11.4 覆盖度必须公开

引擎要自动算出并打印：已编码规则数 / 可编码待补 / 结构性不可判，且结构性不可判要按原因细分。实测相术册：63 条已编码、116 条可编码待补、34 条结构性不可判（活体观察 8、触摸 2、受控气色 8、需定位图 16）。**不公开覆盖度就是把部分覆盖伪装成全覆盖。**

### 11.5 阈值拿不到时：定性档位 + 参照图

源资料常不给阈值（相术书只说"熟了一眼便知"）。此时不要假装有阈值，改为三档定性（low/mid/high），并用原资料里的案例图作档位参照。

**关键约束：参照图只标"外观档位"，不标原书的判定结论。** 若原书案例的分组与规则方向相反（本技能第十节实测过这种情况），把案例结论一起带进来等于把源资料的矛盾注入引擎。

### 11.6 采集引导页要点

单文件 HTML + `getUserMedia`，完全本地：

- 按"最简可判集合"逐张引导（面相册做了 7 张：正面、左 90°、右 90°、掌心、手背、拇指正位、拇指侧位），每张写清角度/光照/遮挡/尺度参照要求。
- 每张卡片标出**该张能支撑多少个槽位**（从 `slots.json` 的 `view` 统计），让用户知道为什么值得拍。
- 拍后即时自检：分辨率下限（<900px 提示不可靠）、平均亮度区间（过暗过亮都提示）。伪代码：
  `lum = Σ(0.299R+0.587G+0.114B)/N`，<60 或 >205 报警。
- 提供"选本地照片"回退路径（无摄像头或浏览器拒绝权限时可用）。
- 一键导出全部照片（按槽位键命名）+ 下载空白观测表。
- 页面顶部**红框声明照片不出本机**，并写明无网络请求。
- 常见坑：`file://` 下部分浏览器会拒 `getUserMedia`，必须准备回退；`v.videoWidth` 为 0 时拍照会得到空图，要先判空。

## 十二、定位图类信息的重绘与核对（图退化为文字时怎么办）

老资料的"图"经常在 PDF 化过程中退化为散排文字：某页检测到内嵌图对象数为 0，但正文里满屏是"天庭""父亲""地阁"这类孤立词。此时**不要凭想象画出图**，按下面四步走。

### 12.1 先确认页面上到底有没有图

```bash
# 内嵌图对象数为 0 且满屏孤立方位词 = 图已退化为文字
python -c "import fitz; d=fitz.open(SRC); print([len(p.get_images()) for p in d][80:85])"
```
若是 0，就必须在交付物最前面写明：**本次是"按文字排布反推方位"，不是"照图抄录"**。这一句决定了后面所有条目的可信度标注方式。

### 12.2 三级置信度口径（必须逐条标注）

| 分值 | 含义 | 例子 |
| --- | --- | --- |
| 0.95 | 源文文字直述，可直接引用 | "右侧代表妻子"、"左耳代表长房长子" |
| 0.7 | 按页面文字排布反推（版面相对位置） | 左列第 3 行与右列第 3 行是否同属中停 |
| 0.5 | 依赖标准约定推断，源文未标方向 | 内八卦是否即标准后天八卦方位 |
| 0.3 | 源文未交代 | 同一名称重复三次各对应何处 |

**凡 <0.95 者一律标"待核对"，并在交付物里显式写明"核对前不得用于判定"。**

### 12.3 抽取时优先抓"结构性关系"，而不是抓坐标

图退化后坐标不可靠，但**格位之间的相对关系是可验证的**。实测收益：

- 四个八卦 3×3 格逐格比对，得 4 条精确关系：男内＝女内；男内＝男外上下翻转；女内＝女外旋转 180°；女外＝男外左右镜像。
- 十二地支男女两图逐格比对：女图＝男图左右镜像，中线二字位置不变，与源文"男顺女逆"互证。
- 男女六亲图的耳位/眼位互为镜像，与"男左女右"体系自洽。

这些关系是**逐格比对得出、不依赖任何外部约定**，可以直接给 0.95，比坐标猜测有用得多。

### 12.4 一定要抓的"镜像约定"

老图十有八九按看图者视角绘制，版面左右与被相者的左右相反。**先在页面上找有没有明说这一点的字句**（实测原书第一列就写着"右侧代表妻子"），找到就直接引用为总纲（0.95）；找不到就必须把两种读法都画出来让人核对，不能默认一种。

### 12.5 交付形态：交互重绘页 + 核对清单（不要只给一张图）

- **SVG 重绘**：把可定位的位点编号（F1、E1、B1…），每个点按置信度上色（绿＝直述、橙＝推定），页面标明"本图为按文字排布反推"。
- **两份表**：位点对照表（位点／归属／依据／置信度／核对框）+ 版面位置表（行／左列／右列／依据／核对框）。
- **镜像切换按钮**：一键在"版面左列＝被相者右侧／左侧"两种读法间切换。
- **核对清单按影响面排序**，并写明每项"影响什么"（例如"第 5 项决定 16 条需宫位定位的断语能否落位"）。
- 勾选状态存 `localStorage`，页面零网络请求，顶部进度条。
- **回填闭环**：核对后把 `conf` 升到 0.95、`basis` 改为"原文直述（经核对）"，重跑生成器刷新；方位定案后再把宫位类槽位补进槽位表，把"结构性不可判"转成"可编码"。

## 十二·补、源文没说清的，去外部找：不可判断项的登记与补证

上一节处理「图退化为文字」；这一节处理下一步，也是用户几乎必问的一句：
「**判不了的那些，能不能上网找到依据，能补的就按它定**」。

分两件事做，顺序不能反。

### 12b.1 先把「判不了」登记成表，再谈补证

不要在正文里零散写「此条待核」。建一张登记表（`infer/unresolved.json`，生成脚本 `build/unresolved.py`），每项固定十个字段：

| 字段 | 说明 |
| --- | --- |
| id | `U-01` 起编，全库唯一 |
| cat | 缺口类型：触觉 / 活体听觉 / 受控拍摄 / 源文方位未定 / 图示退化 / 源文自身冲突 / 样本不可校准 / 性质边界 |
| why | 为什么判不了（写机制，不写「不清楚」） |
| ids | 受影响条目 id 列表（**必须是库里真实存在的 id，脚本要校验**） |
| axis | 受影响的方位表项编号（可选） |
| slot | 受影响的槽位键（可选） |
| ext | 检索结果摘要 |
| adopted | 不采用 / 部分采用 / 采用 |
| verdict | 已采用 / 定案 / 推定采用 / 条件可判 / 两套并存 / 仍不可判 / 常设 |
| fix | **采用后的定义或处理办法**（这是用户真正要的东西） |
| conf | 置信度 |

**这张表是「哪一条能不能判」的唯一口径**，条目级标注一律由它派生（见 12b.3），不得在正文里另立说法。

### 12b.2 外部依据库与采用门槛

另建 `infer/external_refs.json`，每条依据记录：结构化标准内容、来源名称与链接、**与源文的逐项比对结论**、是否采用、置信度、存异说。

采用门槛写死两条，满足其一才采用：

1. **多源一致**（至少两个独立来源说法相同）；
2. **能与源文自述逐格吻合**（把源文图形按它自己的镜像约定换算后，与外部标准逐项对齐）。

两条都达不到的，只记录、不采用。**「部分采用」要显式写清采用哪一半**（例：只采用色名与五行对应，不采用为判定阈值）。

实测最有效的三个手法：

- **拿源文自己的话当锚**。例：源文写「坎代表房后、离代表房前」，而坎在其八卦图上排正中、离在下排正中 → 该图必为上北下南的院落平面。这条推理只用源文，结论却足以定案，比外部资料更硬。
- **用外部标准反向校验源文的读法**。例：外部「百岁流年」十二地支部位，只有按源文「版面左列＝被相者右侧」换算才逐格吻合；换成相反读法则十二个部位全部错位。一条外部标准同时校验了方位与左右约定两件事。
- **多源冲突时，取与已确立体系自洽的那一说**，并把异说一并记录（例：掌上八卦两说，取与后天八卦自洽的一套；源文实际用到的「巽宫」在两说中位置相同，不受影响）。

### 12b.3 三处落库，缺一即等于没做

| 落点 | 内容 |
| --- | --- |
| 槽位表 `slots.json` | 补上被解锁的槽位，并给每个槽位加 `外源补证: true` 标记（**区分「源文直述」与「外部标准」两种来源**） |
| 规则表 `rules.json` | 给新可判的条目补规则，并加 `ext` 字段注明含外部标准 |
| 方位/提取表 | 把 `处理状态`、`结论`、`定案置信度`、`登记项` 回写到原表，让交互页直接显示状态 |

覆盖度报告要跟着改口径：原先按关键词落入「需定位图」桶的条目，在落库后应移入「可编码待补」，并在文档里写清**这次口径变化的数字**（例：已编码 65→75 条，原「需定位图」桶清零）。

### 12b.4 标注要落在六处，缺一处用户就看不见

1. 站点新增独立视图（按 verdict 分组，支持关键词筛到 `U-06`）；
2. 断语表加「判定」列，用徽标区分 `外源补证 / 条件可判 / 不可判`，悬停显示原因；
3. 独立文档页（本册用 `docs/93`）；
4. **每一章的页面**加「判定」列 + 章末「判定标注」段（只列本章被标注的条目）；
5. 目录页写判定统计；
6. 结构化数据加字段（`entries.csv` 的「判定／判定原因」两列、`entries.json` 的 `meta.judge`）。

### 12b.5 顺带一定要抓的自查

统计「不可判」时容易犯两类错，务必自查并写进文档的「口径更正」段：

- **关键词误并**：按 `摸/推/按` 之类的字命中统计，会把判据本身是视觉的条目一并算进「触觉类」。实测 12 条里只有 2 条真属触觉。
- **把可观察误判为「需定位图」**：只要判据用的是可指认的部位名（眉、鼻、口、耳、眼、额），就不需要定位图。实测某流年法的 7 条被误并，实为可直接观察。

另外：外部资料**给不出阈值**是常态（本册 10 条外部依据里没有一条给出数值门槛）。因此气色之类只能定为「条件可判（受控拍摄＋人工定标）」，不要把「找到了色名与吉凶对应」说成「可以判了」。

### 12b.6 诚实收尾

登记表里要明写「仍不可判」的完整清单与其机制（触觉 / 活体 / 听觉 / 样本不可校准 / 性质边界），并说明**外部检索为什么解决不了**。把「部分覆盖」说成「都能判」是这类交付最容易犯的错。

## 十三、必做的校勘核对（写完数据后跑一遍）

**正文层**
1. **重复段落**：同一段文字在多页出现（作者改版痕迹），取首见页，不重复建条。
2. **条序错乱**：正文编号与出现顺序不符（常见「2.」在「1.」之前）。
3. **常见讹字**：形近/音近错字，建条用规范字、摘录用原字，并在校勘页列映射表。
4. **阙文**：口诀中夹着不成句读的四字（如某处只剩「促定久暂」），标疑似阙文。

**图片层（正文层之外，往往更严重）**
5. **同页重复绘制**：同一矩形出现两次 → 按矩形去重。
6. **跨页内容复用**：按内容 MD5 归并，统计每个内容出现在哪些页、哪些案例组。
7. **整页重复**：两页文字与配图都完全相同（本例 P45/P46）→ 合并并写明证据。
8. **同图支撑互斥结论**：同一张照片在不同页被标成不同结论 → 分建条目并互标复用。
9. **标注张数与实际不符**：原文说"以上十五张"，实际去重后 14 张 → 按实际录入，原文标注保留。

## 十四、合规声明（这类内容必须写，别省）

产出物三处（README、站点页脚、校勘页）都要有：

- **性质**：属传统民俗资料，不具科学依据，不得用于医疗诊断、人事决策或任何对他人不利的用途。
- **肖像**：源文含真实人物照片时，影印件与裁切件仅本机保存，`images/` 进 `.gitignore`，禁止外传、公开发布或用于训练；
  图注只描述可见特征，不推断人物身份。
- **著作权**：源文文字与照片著作权归原作者，本知识库为个人学习检索的结构化整理，不替代原书。
- **证据强度**（图册类必加）：写明案例图存在跨页复用的实情与比例，提示引用前先查复用字段。

## 十六、交付与归档：封成一个可长期保存的文件夹

知识库建完，用户下一个动作几乎固定是「给我归档」。别手工拷，写一个可重跑的打包脚本（本册 `build/make_archive.py`），一次做四件事：

| 步骤 | 要求 |
| --- | --- |
| 复制 | 只复制，不动原目录。同名归档目录存在时重建，不要留 `.bak-时间` 之类垃圾 |
| 清单 | 全量 `MANIFEST.csv`，列 `相对路径 / 类别 / 字节 / SHA256`；按类别排序，把 `.git` 压到最后，否则几百行版本库内部文件会淹没资料文件 |
| 封面 | 包级 `归档说明.md`：入口顺序、目录结构、重跑命令、合规边界、可核验方法。**数字全部由脚本计算**，包含 git HEAD，不要手写 |
| 压缩 | 同名 `.zip` 一并产出，写完后 `testzip()` 自检并报条目数 |

命名用 `<项目名>_<版本>_<日期>`（例 `手面相江湖铁断-知识库_v3.0_20260920`），版本与日期由脚本取，避免手工不一致。

**清单是归档的价值所在**：包内文件数与「去掉 .git 后的实际资料文件数」要分别列出，否则用户看到 700 多行会以为包里混了垃圾。说明里另附「先看哪个」的入口顺序，第一个入口固定是单文件站点。

核验口径（写完自检，不要把没验的说成验过）：

- 抽样 20 个关键文件，与原目录逐个比对 SHA256，必须全一致；
- 用清单逐行反查「存在且字节数相符」；
- 从包内站点文件里把内联数据抽出来 `json.loads`，确认条目数、图数、标注数与原库一致；
- `zipfile.ZipFile(...).testzip()` 返回 `None`。

## 十七、踩过的坑

| 坑 | 后果 | 对策 |
| --- | --- | --- |
| 用 `extract_image` 按页存图 | 图与页错配，站点全错 | 单张用 `get_pixmap(clip=rect)`，另存整页影印 |
| 只按 xref 判重复 | 跨页复用的照片 xref 各不相同，判不出 | 按图像内容 MD5 归并 |
| 同页重复绘制未去重 | 编号标注图出现"幽灵框"，编号与照片错位 | 按矩形去重后再编号 |
| 一张一张读裁切图写描述 | 数百张读不完，上下文爆掉 | 按页读编号标注图，一批页落盘一次 |
| 图注写"面相较好"这类空话 | 与断语无法对照，读者用不上 | `feat` 按原书判据词汇表写 |
| 只做断语→图单向链接 | 读者在图鉴里看不到结论 | 双向绑定 + 反向覆盖率检查 |
| 复用信息只写在数据里 | 读者看图时不知道证据不独立 | 图卡上显式渲染橙色复用警示 |
| 章节表与数据文件分离且不校验 | 改名后整章静默消失 | 生成器加 assert |
| HTML 模板用 `str.replace` 注入数据 | 正文含 `</script>` 会破格 | `json.dumps` 后把 `<` 转 `\u003c` |
| 在 personal 目录建站 | 污染用户桌面/文档 | 一律建在 workspace 或用户指定目录 |
| 校勘页数字手写 | 与产物不符（如影印页数） | 数字全部由生成器计算 |
| 用 `s.replace(锚点, 锚点+新增)` 打补丁 | 脚本被执行两次时**重复插入**（本册在归档说明里插出过两行相同表格行） | 补丁写成「目标串不存在才插」，或写完立刻 `s.count(关键词)` 校验为 1 |
| 按关键词统计「不可判」 | 把视觉可判的条目误并入触觉、把可观察的误判为需定位图 | 登记表按机制人工确认，不按字词命中；口径更正写进文档 |
| 外部依据只记结论不记比对 | 无法判断是否可用、无法回溯 | 每条依据必写「与源文的逐项比对结论」与存异说 |
| 判据部位名可从原文指出，却仍标为不可判 | 覆盖度虚低，用户以为做不了 | 判据是眉/鼻/口/耳/眼/额一类可指认部位者，一律不算需定位图 |
