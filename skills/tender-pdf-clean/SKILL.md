# 投标 PDF 清洗分层流水线

把一份或一批中文投标文件 PDF 处理成"干净、分层、带元数据"的纯文本。核心库是 PyMuPDF（fitz），不依赖任何云端 OCR。

## 三步流水线总览（串联复用入口）

投标 PDF → 向量库 的完整链路，三步链式接力，全程 PyMuPDF 在隔离 venv 跑，无云端依赖：

1. **清洗分层** `clean_pipeline.py`：源 PDF → `cleaned/clean_*.txt`（分层纯文本 + 表格标记 + 附件占位 + 9 字段元数据）。先字节级探针判可处理性，空壳直接告知，尾部损坏走页树重建。
2. **标准 MD** `to_markdown.py`：TXT → `md/*.md`（#/## 标题、原生管道表、![图片]语法、> 引用块、隐私脱敏、元数据块置顶）。
3. **向量分块** `to_chunks.py`：MD → `chunks/*_向量分块.md`（## 为单元、3000 字上限续拆、路径锚点、分类标签、关键词、--- 分隔）。

新项目决策树：探测可处理性 → 不可恢复如实告知 → 可恢复三步串行 → 结构完整的同法生成，半损毁/空壳不纳入。
```
PY=.../envs/pdfproc/Scripts/python.exe
$PY clean_pipeline.py <源PDF> <cleaned/clean_X.txt>
$PY to_markdown.py   <cleaned/clean_X.txt> <md/X.md>
$PY to_chunks.py     <md/X.md> <chunks/X_向量分块.md>
```
强处：忠实可审计，局限摊明不编造。弱处：财报扫描件/无边框表格/尾部损坏章节只能标"不可得"，需另接 OCR 补盲点。

## 何时用
用户提交 `.PDF` 投标文件，要求：清理冗余（页眉页脚/水印/空白页/重复扫描）、OCR 纠错、按章节分层、区分商务/技术/报价/附件、标记表格、提取元数据、输出分块纯文本。

## 环境
- 优先用隔离 venv：`C:\Users\<USER>\.workbuddy\binaries\python\envs\pdfproc\Scripts\python.exe`
- 安装：`...python.exe -m venv <env>` 后 `pip install pymupdf`（沙箱拦截 cmd.exe 调 setup.bat，须自建 venv）。

## 处理流程（严格顺序）

### 0. 字节级可处理性探针（必须先做）
读前 32 字节与首 2000 字节频次：
- 无 `%PDF` 头、开头是 `\x00\x03\x01\x03…` 填充字节 → **不可恢复空壳**，直接告知用户，不要硬跑。
- 有 `%PDF` 头但 `fitz.open` 报 0 页 / 无 trailer / 无 startxref → 尾部被覆盖，进入步骤 1 重建。
- 正常 `%PDF` → 直接进入步骤 2。

### 1. 破损 PDF 页树重建（recover.py 思路）
适用于 iTextSharp 等生成、尾部 xref/trailer 被截断的文件：
- 扫描全文所有 `N G obj` 块，定位顶层 `/Pages` 节点（各有 `Count`，父节点为被覆盖的对象）。
- 合成 root（如 `R=7679`）与 Catalog（`C=7680`），将各 `/Pages` 的 `/Parent` 重连到 root。
- 重写 xref 表 + trailer（`/Root R 0 R /Size ...`），保存为 `zy_repaired.pdf`。
- 局限：仅恢复页树骨架；尾部破坏落在内容流上的章节（如报价/附件）文字层仍丢失，属源损坏非缺陷。

### 2. 页眉页脚剔除（三重规则）
- 坐标区：`y0 < 0.09*H` 记顶部串、`y1 > 0.92*H` 记底部串。
- 跨页频次：`THR = max(3, int(NP*0.02))`，频次 ≥ THR 的字符串进 `HEAD_RUN/FOOT_RUN`。
- 显式签名：`投标文件`、`^第X章`、嵌入财报特有的 `中汇/ZHONGHUI/zhcpa` 页眉、`抗州/UDC` 乱码页脚、纯数字页码行。
- 逐块按坐标 + 命中集合剔除；正文块保留 `(y0,y1,text)`。

### 3. 章节分层
- `CHAP_MOD = {第一章:商务文件, 第二章:技术文件, 第三章:报价文件, 第四章:附件证明}`。
- `detect_chap_sec`：**只扫页面前 6 个非空行**（避免目录页全文多章污染），用 `SIG_CHAP/SIG_SEC` 捕获。
- `clean_title()`：剔除章节/节标题里的目录引导点与页码。正则 `r'\.{2,}\s*\d*\s*$'`（末尾页码可无）。**关键陷阱**：必须对正文 TOC 行也做同样剥离，否则路径干净了、正文 TOC 仍带点。

### 4. 附件与图片页
- `is_image_scan`：有图且文字 < 200 字 → 扫描件占位。
- 证照类（命中 营业执照/资质证书/安全生产许可证/审计报告/开户许可证/身份证/体系认证 等）→ 归入 `【附件证明】`。
- **源损坏特判**：若整份文件尾部章节标题页丢失（如中远海运），末尾图片型无关键词页会错误继承上一可读模块（技术文件），造成"路径技术文件 + 正文附件证明"矛盾。对策：对这类页打中性标签 `【图片扫描件·章节未明（源文件尾部损坏）】`，不强行归模块，并在交付说明里讲清。

### 5. 表格标记
- `page.find_tables()` 命中 → 输出 `【结构化表格】`，单元格用 ` | ` 分隔，完整保留行列。
- 局限：无边框表格 `find_tables` 识别不到，会退化为纯文本段落。

### 6. 元数据提取（9 字段）
全页读文字，正则抓：项目名称、报建编号、标段号、投标人、法定代表人、项目负责人/项目经理、投标日期、工期、投标保证金。
- 全页读取（不只首页），`clean_val()` 去重标签。
- **投标保证金常不在文字层**（在银行保函原件），抓不到就标"（文本层未识别，见原件）"，如实告知。

### 7. 输出格式
- 开头统一元数据块 + 清洗统计行（总页数/空白/重复扫描/图片占位/含表/跳过）。
- 每段 `[层级路径] 【模块】 > 第一章… > 第一节…`（三级：章/节/子条目）。
- 纯文本，**不生成 Markdown**；表格用 `【结构化表格】` 显式标记；图片占位用 `[附件证明] 图片占位` 或 `[图片扫描件]…`。

## 性能实测（某高速公路 1 标，9 份 10768 页）

单份 158s~477s，**正比于页数**，9 份串行约 35 分钟。
主耗时是 `page.get_text("dict")`（约 3.4s/60 页），**不是 `find_tables`**（1.3s/60 页）。
给 `find_tables` 加前置信号筛候选页后单份耗时基本没变 —— 别再往表格抽取上做优化，
要提速只能从减少 `get_text` 调用次数入手（如按页块类型分流，图片页跳过 dict 抽取）。

## 交付前必做：语法自检 + 小样本实跑（实战教训）

**`py_compile` 通过 ≠ 代码路径被执行过。** 实战中 `clean_pipeline.py` 有一处
缩进错误（`for r_ in rows:` 被编辑操作弄丢缩进，跑到文件首列），`py_compile` 报错了，
但此前 9 份产物**全部是从旧的 cleaned txt 重生成的**（因为脱敏/去标记的修复都在
`to_markdown.py` 侧，cleaned 未重跑），所以那条错误路径一次都没被触发，
质检也就全绿 —— 交付后才发现脚本本身是坏的。

两道防线，缺一不可：

```bash
# 1) 五个脚本全部语法自检
for f in scripts/*.py; do $PY -m py_compile "$f" && echo "OK $f"; done

# 2) 截 60 页小样本实跑全链路（PyMuPDF 新版 insert_pdf 用关键字参数）
$PY -c "import fitz; d=fitz.open(SRC); o=fitz.open(); o.insert_pdf(d, from_page=0, to_page=59); o.save('mini.pdf')"
$PY scripts/clean_pipeline.py mini.pdf cleaned/mini.txt
$PY scripts/to_markdown.py   cleaned/mini.txt md/mini.md "测试"
$PY scripts/to_chunks.py     md/mini.md chunks/mini_向量分块.md
```

**教训**：修复某个阶段的缺陷后，若产物是从上一阶段产物重生成的，
必须单独验证被修复的那个阶段的脚本本身能跑。质检只能验产物，验不了脚本。

## 已知坑（务必规避）
1. TOC 引导点：标题路径和正文行都要清，只清一处会留尾巴。
2. 目录页：必须只扫前 6 行，否则目录列出的全部四章会污染当前页路径。
3. 源损坏尾部：绝不给末尾页强行套用上一模块，用中性标签 + 说明。
4. 隐藏依赖：cmd.exe 被沙箱拦，别用 pdfkit 自带 setup.bat；自建 venv 装 pymupdf。
5. 不可恢复壳：开头填充字节无 %PDF 头，任何工具都救不了，第一时间告知用户而非空跑。
6. 文字层误识别"第X节"为"第X章"：提取偶漏"节"字，使"第三节 工期保证体系"变"第三章工期保证体系"。SIG_CHAP 若不限制，会把模块提前切到报价（第三章→报价文件），技术内容大量丢失（实战 中铁十八局 技术 1→249）。对策：SIG_CHAP 只认含"文件/附件"的真章标题（商务文件/技术文件/报价文件/附件），排除误识别的"第X章"。
7. 缺第二章标题页的标段：个别标段 PDF 无"第二章 技术文件"标题页（技术标可能是扫描封面或独立分册），技术内容全被挂成商务（实战 中铁十局 技术 0→574）。对策：主循环加 tech_signal（页面强命中≥2 个技术标准节标题词：总体施工组织布置及规划/主要工程项目的施工方案/工期保证体系/安全生产管理体系/工程质量管理体系/环境保护水土保持/文明施工文物保护/项目风险预测与防范/施工方案方法与技术措施）兜底，商务之后、报价之前归技术文件，并合成"第二章 技术文件（第一阶段）"章标题贯穿 MD 与分块（属推断，交付时说明）。

## 扩展：招标文件 → 结构化 Markdown（带命名 / 索引表 / 向量标签）
当用户要求把一批招标文件 PDF 转成"结构化 MD、目录镜像、命名=项目+标段+结构化"时，在 clean 分层基础上叠加以下产物（实战 99 份验证通过）：

1. **目录镜像**：`os.walk` 递归收集所有 PDF，`outdir = OUT/相对源的子目录`，保持与源相同目录结构。
2. **每文档结构**：YAML 前置元数据（22 项通用字段：报建编号/标段号/招标人/代理/建设地点/总投资/限价/工期/保证金/下载时段/答疑截止/补遗/投标截止开标/联合体/企业资质/关键人员/履约保证金/踏勘…）→ 4 张全局索引表（时间节点 / 资格与废标 / 关键人员 / 违约处罚，均做**优雅降级**：字段空则填 `—` 或"详见…"，不报错）→ 正文分层（章节用 `##/###`，表格用 `|` 管道，复选符 ☑/⬜→【已勾选】/【未勾选】）→ 每节末 `> 向量标签：#xxx` → 联系/文号附录。
3. **三级命名兜底**（实测 99 名全清）：
   - ① 优先用 `标段名称` 字段（含"工程"或 `\d标` 才采纳）；
   - ② `cover_title()`：先救援 `项目名称[:：_]`/`工程名称：` 含"工程名+标段"；再取封面段（截断到 招标文件/招标人/招标代理 之前）；**去大字距空格**（封面常把 `目  录`、`标 段 号` 撑开 → `.replace(' ','')` 后再匹配）；遇 `目录`/`第X章+招标公告`/价表关键词（`投标报价汇总表`/`综合单价分析表`/`第100章`）则放弃、交文件名兜底；
   - ③ 文件名兜底：去 `【】`/`（第X次）`/锅炉板词（`招标文件|招标正文|定稿|盖章|上网版|上网稿|上网|发行定稿|最终版|补遗|补充文件|施工补充文件|施工招标|发标|版|第一次~第四次`）；去多字符 `—` 与首尾孤立 `-`；**展开 `（N标）`→`N标`、`(N)`→`N标`**；捕获 `【】` 内标段标记（如 `S99主体3标`/`施工1标`）用于消歧同名碰撞；**平衡孤立括号** `_bal()`（未闭合 `(1标` 从最右删孤立 `(`）。
4. **命名 strip 集必须含全角 `）`（U+FF09）**，否则尾随 `）` 残留（半角 `)` 与全角 `（` 都易漏）。
5. **不要全局去连字符 `-`**：会误伤 `环线-射线` 这类编号和日期 `2024-08-22`；只去多字符 `—` 与首尾孤立 `-`。
6. **proj 内 strip 不得剥 `）`/`)`**：否则 `（主体）2标` 会被切成 `（主体2标`（把 `）` 当尾随剥掉后再拼 `2标`）。尾随孤立 `）` 交给最终 `cand.strip` 处理。
7. **图片型扫描件优雅降级**：若 `fitz` `get_text("text")` 全文长度=0（无文本层），仍输出完整 YAML+索引表+附录骨架，正文 `# 全文` 留空，**绝不谎报内容**；在交付说明里点名这几份。
8. **源 PDF 损坏**：`fitz.open` 失败（xref/trailer 被截断或 0 页）直接跳过该份并记录 FAIL，不要硬跑整批；如确需抢救可走步骤 1 页树重建。
9. **质量自检脚本**：遍历产物统计 YAML 头部/索引表/向量标签/章节数/表格数 覆盖率（实战 98/98 全过），并 `glob` 比对各子目录文件数与源一致。

## 扩展2：向量库分块（to_chunks.py，承上 MD 产物）

把一份已生成的投标 Markdown（to_markdown.py 产物）切成适配向量库导入的独立文本块：

1. **最小单元**：`##` 二级小节为一块；正文超 3000 字按空行拆段落续成子块，路径锚点追加 `（第N段）`（如 `【章节路径：第一章 商务文件-第八节 资格审查资料-（第2段）】`）。源 MD 无 `###` 时，长节自然生成续拆块。
2. **锚点格式**：每块开头 `【章节路径：第一章 X-第一节 Y（-子块）】`；章节标题去全角括号修饰（`商务文件（第一阶段）`→`商务文件`），与用户给定示例对齐。
3. **分类标签** `【分类：商务/技术/报价/财务附件/资质证件】`：
   - 第四章（附件）→ `财务附件`（命中 审计/财务/报表/报告/资产负债/利润/附注/会计/验资/现金流量）否则 `资质证件`；
   - 第三/二章 → 报价/技术；
   - 第一章等 → 仅当命中**强证书词**（`资质证书|安全生产许可证|认证证书|体系认证|执业资格证书|注册证书`）才归 `资质证件`，**不可**用 `营业执照`（"营业执照号码"是字段标签，会误判商务表为证件）。
4. **关键词**：章节/子块标题去掉"第X章/第X节"前缀后拆词 + 业务词典命中（投标/保函/工期/工程量清单…）+ 全局词（G99/示例编号/C99/机电标），逗号（`、`）分隔，置于块末尾 `关键词：…`。
5. **分隔**：块间 `\n---\n`，便于批量导入。
6. **自检**：每块必须有 `【章节路径：`+`【分类：`+`关键词：`；最大正文≤3000；`\n---\n` 数 = 块数−1；无块含多个路径锚点（防跨章合并）。
7. **诚实边界**：`财务附件=0` 可能出现在审计报告是附件扫描件的标段（文字层为空，仅图片占位），如实标注，不要编造财报文本。
8. **长表格续切**：工程量清单等超大表是连续无空行、单段远超 3000 字，`chunk_lines` 仅按空行切会出超 3000 字大块（实战 中铁十局 曾出现 6567 字块）。对策：单段落超长时内部按行续切，且若是表格（`|` 开头）每段重附表头行 + `| --- |` 分隔行，保证每段都是合法 MD 表。

## 扩展3：Excel → 工程造价 RAG 结构化 Markdown（excel_to_markdown_v2.py + run_excel_v2.py）

把 xlsx/xls 投标报价表转成适配 BGE/智谱 Embedding 等中文向量模型的结构化 MD（实战 89 份重制）。**两类文件、两种待遇**，由 `detect_boq_header` 自动判别：

- **清单类（固化清单/已标价工程量清单）**：表头含 `子目号/子目名称/数量/单价/合价` → 完整六段结构（见下）。
- **非清单类（单价分析表/建安工程费用表/报价汇总表/材料暂估价表/合同用款表/费率表/措施费表）**：套同样外壳（YAML+语义前置+索引+分隔符），但**保留原表列**（不强塞清单表头），因列结构（人工费/材料费/定额直接费…）与清单不同，硬转会丢字段、违反"禁止删减任何原始条目"。

**两个结构性决策（用户确认）**：
- **按章节工作表切分**：一份工作簿 → 多份 MD，每张工作表 = 一份独立文档，落入 `<OUT>/<相对源>/<工作簿名>/<工作表名>.md` 子目录（文件间数据完全隔离，向量检索粒度更细）。固化清单工作簿常含 100/200/300/400/600/800 多章，各成一份。
- **非清单文件套外壳保原表**：同上。

**强制输出结构（每份文档）**：
1. **YAML 多维元数据**：`data_category: 工程造价-投标清单` / `project_full_name` / `bid_company` / `chapter_serial`(100/200/300/400…单章值) / `chapter_full_title` / `total_cost_yuan`(优先按节点核名在报价汇总表定位，否则章次累加) / `material_tags`(钢筋/钢绞线/混凝土/支座/伸缩缝…自动探测) / `work_type_tags`(路基/桥梁/路面/排水/安全设施/临时措施…) / `source_document_name` / `doc_subtype`(工程量清单|报价附表) / `chunk_recommend: 600token/块`。
2. **长文本语义前置描述**（≥120 字，纯自然语言，主动释义 HPB300/HRB400/UHPC/拉森桩/预制小箱梁 等专业词，强化向量特征）。
3. **分层明细表**：清单类表头 `子目编号｜分项工程名称｜计量单位｜工程量｜综合单价(元)｜合价金额(元)｜工艺材料备注`；一级子目用 `### 小标题`，二级子项逐条罗列，末尾 `**本节合计：x 元**`；零金额/0元/合计行完整保留。
4. **分项造价解读**：每个一级子目配套分析文本（规模/主材占比/难点/单价构成），杜绝纯表无文字导致检索失效。
5. **全章节造价汇总校验表**：脚本汇总合价 vs 报价汇总表登记值，标注一致/差异。
6. **末尾检索索引区**：`#检索关键词：`(≤20 核心词，空格分隔) + `#分块说明：`(按一级子目分割，块重叠10%) + `----------文档结束----------` 分隔符。

**关键实现要点（踩坑沉淀）**：
- **层级解析** `classify`：`-` 开头编号**有金额=叶子、无金额=子分组**（如 `-a 陆上钻孔灌注桩`）；`202-1` 有金额=叶子、无金额=一级分组；纯数字 `403`=中分组；`合计` 出现在编号/名称/单位任意处→合计行（捕获金额，不并入明细）；无父分组的叶子以自身为 `###` 小标题（行内编号留空避免重复）。
- **金额格式**：无千分位；`round(x,6)` 清理二进制浮点伪影（`63004.03999999999`→`63004.04`），非四舍五入，保留原始小数。
- **元数据抽取** `extract_meta`：**必须带冒号**才认（`项目名称：`/`投标人：`），排除表头列名"项目名称"（无冒号）误抓到"投标报价（元）"当项目名。
- **表头探测** `generic_table`：取前 12 行中首个 `非空率≥0.6 且非整行同值 且 ≥3 个不同值` 的行，排除 `项目名称：/投标人：` 前言行被当表头。
- **性能**：投标表实际列数极少，读网格时 `maxc = min(ws.max_column, 120)` 钉死上限，否则 `XFB147`(16382 列) 虚宽列导致逐格读 16382 列、单簿 3 分钟；钉死后 27 秒/簿。
- **读取**：`openpyxl.load_workbook(data_only=True)` 普通加载（read_only 不暴露 merged_cells）；xls 用 `xlrd`。**合并单元格展开**回填左上角值；**尾部空列/空行裁切**。
- **隐私脱敏**：身份证 `^\d{6}(\d{8,11})\d{4}$`→前6+`******`+后4；手机 `^(1[3-9]\d)\d{4}(\d{4})$`→前3+`****`+后4（捕获组数须匹配）。单元格 `|`→`\|`，控字符 `\x0d` 清除。
- **批驱动** `run_excel_v2.py`：`os.walk` 收集 xlsx/xls → 逐簿转多 MD 入子目录；**转换成功后删旧平铺 md(`<簿名>.xlsx.md`)** 避免新旧并存（PDF 的 md 不动）；**断点续跑**（子目录非空则跳）；失败写 `fail_excel_v2.log` 不中断；日志 `progress_excel_v2.log`。

**辩证提醒**：规范按"标准投标清单"设计，但真实投标包里 ~2/3 是非清单附表。把它们强行套清单表头会失真，故对非清单类"保原表 + 套外壳"是忠于"不删减原始条目"的更优解；若用户只要标准清单，可只跑 BOQ 类 sheet。

> **断点续跑陷阱（实战 X1）**：`run_excel_v2.py` 的子目录非空即跳过逻辑，会静默跳过已存在的旧版（无 YAML 头）产物，导致部分文件未被 v2 重制（主体施工曾混入 361 份旧 schema md）。重制前应先清空目标子目录或加版本标记，避免新旧混存被跳过。

> **章节结构缺章标题塌块（实战 X2）**：`to_chunks.py` 的 `parse_pieces` 以 `#` 章 + `##` 节为切分骨架，`build_chunks` 又用 `if chapter is None or section is None: continue` 丢弃缺章的节。若某 PDF 转出的 MD **没有 `#` 章标题、直接以 `## 节` 开头**（如纯"已标价工程量清单"），整篇正文会全部漏进 `meta_lines` 被 dump 成**单块 1.29M 字**的不可用巨块。修复已落地：`parse_pieces` 的 `##` 分支在 `chapter is None` 时兜底赋章名"投标文档正文"，让该节正常进入 piece 并被 `chunk_lines` 切分；另在 `build_chunks` 加 `if not pieces:` 整文分段兜底（合成锚点 `工程量清单-清单明细（第N段）`、分类 `报价`）。**交付前必须跑"块数/锚点/分类/关键词齐 + 单块≤3000"的全量质检**，否则这种塌块会静默漏网。

> **表格单元格孤立代理字符（实战 X3）**：个别 PDF 经 pymupdf `page.find_tables().extract()` 抽出的单元格文本会混入**孤立代理字符（lone surrogate，U+D800~U+DFFF）**。`clean_pipeline.py` 以 `encoding="utf-8"` 写出时会在表格行 `f.write(row+"\n")` 处抛 `UnicodeEncodeError: surrogates not allowed`，导致整份清洗**中途崩溃**——header 写完、正文表格行写到一半，留下 size>0 的半截 ctxt，该实例不产出 md/chunk（断点续跑还会把它当"已存在的清洗文本"复用、拿半截去建 md，更糟）。修复已落地：在 `clean_pipeline.py` 顶部加 `S(t)` 剥离孤立代理字符，并在正文拼接、表格单元格抽取、元数据写出三处统一应用；批量驱动器 `run_pdf_tree_v2.py` 同步改为"流水线(md+chunk)未完成即强制重洗"，覆盖半截 ctxt、保证幂等。现象识别：某投标人多个副本中仅 1 个副本 ctxt 明显偏小（如 200KB vs 同投标人其他副本 2~3MB）且对应 md 缺失，即是此坑。

> **脱敏漏表格行（实战 X4，比 X3 更隐蔽）**：`to_markdown.py` 若只在正文分支调`mask()`，表格行走 `flush_tbl()` 独立拼装就会**完全绕过脱敏**。而身份证恰恰大量出现在人员表、资质表、社保表里——正是表格。现象：`qc.py` 报「未脱敏身份证 N 处」，逐条看全是 `| 证件号码 | 310110197004043693 |` 这种表格行。修复：`rows = [mask(r) for r in rows]` 放在 `flush_tbl()` 内、分隔行拼接之前。

> **身份证正则误抓统一社会信用代码（实战 X5）**：宽松式 `\d{6}\d{8,11}\d{4}` 会把 18 位纯数字的**统一社会信用代码**（如 `911306817216042341`）、保函编号一并当成身份证脱敏，导致企业资质信息被误伤、检索失真。修复：改用 **GB11643 校验位验证**——
> ```python
> ID_RE = re.compile(r'(?<![0-9])(\d{6})(19|20)(\d{2})(0[1-9]|1[0-2])([0-2]\d|3[01])(\d{3})([0-9Xx])(?![0-9])')
> W = [7,9,10,5,8,4,2,1,6,3,7,9,10,5,8,4,2]; C = "10X98765432"
> # 校验位不符则原样返回，不脱敏
> ```
> 注意边界断言用 `(?<![0-9])` 而非 `(?<![0-9A-Za-z])`：表格单元格渲染成 `| 310110197004043693 |` 时，前一个字符是空格，用 `0-9A-Za-z` 字符类做负向断言虽能通过，但把 `X` 结尾的证件与紧邻字母的场景一起挡掉了，反而漏脱敏。**校验位验证才是真正的过滤条件**，边界断言只管不跨越数字。
> `qc.py` 必须用同一套校验位口径统计，否则报出的数字不可信（实战中一度出现"修完数字反而上升"的假象）。

> **原件表格串行，层级标记混入单元格（实战 X6）**：某些标段的 PDF 里，`[层级路径]` 这类我们自己注入的标记会被表格抽取当成单元格内容抓回来，在 MD 里留下一行 `| [层级路径] 【商务文件】 > 第一章 ... |`，插在技术方案表格中间，极突兀。修复两处：清洗阶段 `cells = [c for c in cells if not c.startswith("[层级路径]")]`，MD 阶段 `rows = [r for r in rows if "[层级路径]" not in r]` 兜底。质检时用 `CLEAN_MARK = re.compile(r'\[层级路径\]|【结构化表格】|【表格结束】')` 全量扫产物，出现即为残留。

## 扩展5：PDF 报价单 → 工程造价 RAG 结构化 Markdown（pdf_boq_v2.py + run_pdf_boq_v2.py）

把 PDF 里的「报价单/工程量清单」挑出来，用**扩展3 的 v2 六段结构**（YAML 多维元数据 + 长文本语义前置 + 分层明细表 + 分项造价解读 + 章节汇总校验 + 检索索引）重做成专用文档。**复用 `excel_to_markdown_v2.py` 的渲染函数**（`build_boq/semantic_desc/cost_interpret/detect_materials/detect_worktype/build_keywords/yaml_block/fmt_num/mask`），只新增「PDF 表格抽取 → grid」一层；产物与 Excel 同 schema，可被同一套向量检索消费。

**两个结构性决策（用户确认）**（与扩展3 一致）：
- **处理范围 = 全部已处理项目的所有 PDF**（主体施工/机电标/路面工程/地面道路/路面/桥梁施工 共 681 份），逐一挑出含报价单表格的页，无则如实标 `NO_BOQ` 跳过。
- **扫描件 = 接 OCR 补识别再转**（见下"OCR 环境坑"）。

**PDF 表格抽取（自研，不用 `find_tables`）**：无边框 BOQ 表几何检测不可靠（`find_tables` 会把"表4-2-1 工程量清单"标题当表头，真列头漏检），改用：
1. `page.get_text("words")` 取词盒 `(x0,y0,x1,y1,text)`。
2. **聚行** `cluster_lines(words, tol=4.0)`：按 `y0` 聚行（±4pt 容差），行内按 `x0` 排序。
3. **表头识别** `is_boq_header`：含 `子目号/项目编码/清单编码` 且含 `单价/合价/数量/工程量` → 判 BOQ；各单元格 `x` 中心做**列锚点**。
4. **数据行靠锚点吸附对齐列**：每个词按 `x` 中心找到最近锚点（距离 ≤60pt），落入对应列；处理跨列合并、散落词。

**修复散字/合并词（实战踩坑）**：
- **表头散字列错位**：表头"子目名称"被渲染成"子/目/名/称"4 个独立单汉字词 → 9 列表头、数据整体错位。加 `merge_cjk(line_words)`：把相邻单 CJK 字（用 `unicodedata.name` 含 `CJK` 判定）合并成一个词，数据行各列间距大不受影响。
- **编号名称合并词**：pymupdf 把"102 工程管理"当一个词 → 名称列空。加正则拆回：`^(\d[\d\-]*[a-zA-Z]?)\s+(\S.*)$` 拆成 子目号/名称。

**章节切分靠「子目号前缀推导」**（不依赖页内"第X章"标记，标记易漏/跨页粘连）：
- `serial_from_code(code)`：`200-1→200, 403-5→400, 102→100, 300-2-5→300`（`int(m.group(1))//100*100`）。
- **公路工程章号字典** `SERIAL_TITLE`：`100总则/200路基/300路面/400桥梁/500隧道/600安全设施/700绿化/800管理养护`；`if ser not in SERIAL_TITLE: continue` 过滤假章（如把"28cm""50）"错吸成章0）。
- 空编号/`-a` 行继承上一行章节（`last_serial`），保证续行不丢章。
- 每个章 = 一份独立 v2 文档：`报价单v2/<serial>_<章名>.md`（数据隔离，向量粒度到章）。

**关键实现要点**：
- **金额**：无千分位、`round(x,6)` 清浮点伪影、不四舍五入；纯文本层抽出的数字已无格式，比 Excel 更省心。
- **元数据**：优先用驱动器传入的 `meta_project/meta_bidder`（从目录/文件名推导），PDF 内 `项目名称：`/`投标人：` 正则补抽（带冒号才认）。
- **封面/页码行剔除**：含 `第X页|清单第` 且不含 `子目` 的行跳过，避免页眉页码污染数据。
- **渲染复用**：`chapter_to_md` 把 grid 喂给 `E.build_boq(norm_grid, 0)`，六段套用扩展3 全部逻辑；YAML 占位 `project_full_name: ""` 用 `replace` 注入 meta（不重建字符串）。

**OCR 环境坑（沙箱实测，务必先读）**：
- **结论已于 2026-09-29 更新**：本机默认 OCR 引擎为 `paddlevl-ocr`（PaddleOCR-VL-1.6），入口 `bash "C:/Users/<USER>/.workbuddy/skills/paddlevl-ocr/scripts/pdocr.sh" --input <路径> --out <目录> [--dpi 200] [--resume]`。请优先使用它。
- **旧结论存档**：`paddlepaddle 3.3.1` 的**静态模型路段**（PP-OCRv5 / PP-StructureV3）在 oneDNN/PIR 运行时抛 `NotImplementedError: ConvertPirAttribute2RuntimeAttribute not support [pir::ArrayAttribute<pir::DoubleAttribute>]`，禁用 oneDNN 环境变量（`FLAGS_use_onednn=0` 等）仍崩；降级 `paddleocr==2.7.3` 因 safe-delete 钩子阻断 pip 卸载 cv2 失败；新 venv 装 `paddlepaddle==2.6.2` 腾讯镜像无此旧版。
  2026-09-29 复测确认：PaddleOCR-VL-1.6 走 `paddle_dynamic` 动态引擎，含静态版面模型 `PP-DocLayoutV3` 在内**均不复现该崩溃**，故上述「完全不可跑」的结论对 VL-1.6 不成立。
- **替代方案 = rapidocr-onnxruntime**（纯 ONNX，不依赖 paddlepaddle）：`pip install rapidocr-onnxruntime onnxruntime`（腾讯镜像可装），模型随 wheel 内置、首次推理免联网。**装法关键**：若 venv 已有 `opencv_contrib_python` 而 rapidocr 依赖 `opencv-python`（另一发行名），pip 会卸载旧 cv2 触发 safe-delete 钩子拦截 → 用 `pip install --no-deps rapidocr-onnxruntime onnxruntime` 绕开 opencv 替换。
- **列对齐的正确做法（关键，曾走错路）**：`RapidOCR().ocr(img)` 返回**整行**合并字符串（不给逐词坐标），若据此"尾部三数猜列"质量极差（子目号整列丢失、`021` 乱码）。正确做法：绕过 `ocr()`，改调 `ocr.text_detector(img)` 取**逐格多边形框** → `ocr.get_crop_img_list(img, det_boxes)` 逐格裁切 → `ocr.text_recognizer(crops)` 逐格识别，得到与 pymupdf 同构的「词+坐标」。`page_words_ocr` 把像素坐标×`scale` 转 PDF 点后，**直接复用文本路径的 `cluster_lines` + 表头 x 锚点吸附对齐**（见上"PDF 表格抽取"），列结构立刻正确。
- **行缝合要做在列对齐之后（结构化后缝合）**：OCR 常把"子目号行"与"名称(及金额)行"拆成上下两行。先在词盒层聚类对齐成 `[code,name,unit,qty,price,amount]` 行，再用 `stitch_rows_structured`：若某行首词像子目号但名称缺失、紧邻下一行无子目号却含汉字 → 吞并续行的名称及其缺失数值。注意**不要在词盒层预缝合**（曾因"单位格'总额'含汉字"导致误判漏合并，失效）。
- **回填补值**：利用工程量清单恒等式 `合价 = 数量 × 单价`（`backfill_amounts`），仅当缺失列可由另两列唯一推出时才算，零风险。对"右侧三列整片一起漏检"的行无效（见下天花板）。
- **质量天花板（沙箱实测，务必先读，避免无谓调参）**：子目号 75–96%、名称 70–94%（对齐正确，检测到即落对列）；**数量/单价/合价仅 64–72%**——轻量 OCR 在这批扫描件上对右侧长串数字列系统性漏检约三成，且三列常整片一起缺失，回填救不回。**已证伪的杠杆**：DPI 300 vs 220 金额率几乎不动；灰度/CLAHE/二值预处理反而把金额列腰斩（64%→22%，不是对比度问题，是识别模型对数字串召回不足）。缺失单元格标 `·`、整文件标 `ocr_derived` 溯源。输出质量"结构对、数字约七成准"，需人工补差额。
- **扫描件检测必须全篇抽样，不能只看前6页**：`pdf_has_text`（前6页 `get_text("words")`>20）会把"封面/目录/盖章页扫描 + 正文文本"的报价单误判扫描跳过（实战漏掉 `10标投标报价文件.pdf`、各标段 `第三卷扫描件.pdf` 等真实投标人报价单）。改用 `pdf_any_text`：**前6页有文字→文本型；前6空但中间/末尾抽样有文字(>8词)→仍文本型(走 pymupdf)；仅当全篇抽样均无文字→纯扫描**。纯扫描再按文件名含 `报价/清单/单价/工程量/投标报价` 路由：是→`convert_pdf_ocr`(rapidocr)，否→`SKIP_DRAW`(图纸不浪费OCR)。
- **抽取必须逐页流式，否则内存爆炸**：`extract_chapters`/`extract_chapters_ocr` 每页处理完即丢弃词盒，只保留解析后的行与全文串；切勿把全篇每页词盒都 `append` 到列表再统一处理——568 页大 PDF 会让进程涨到 **800MB+** 并把并发 OCR 进程 OOM 静默杀掉(exit 1 无 traceback)。遇 OCR 整页崩，单页 `try/except` 返回 `[]`，不要整篇 abort。

**批驱动 `run_pdf_boq_v2.py`**：6 元组 `源根→输出根`；`os.walk` 收集 681 份 → **断点续跑**（已存在 `报价单v2/` 且含 md 则跳）→ `pdf_any_text` 分流 → 文本件 `convert_pdf` / 纯扫描报价单 `convert_pdf_ocr` / 纯扫描图纸 `SKIP_DRAW` → 分类日志 `OK/OK(OCR)/SKIP_DRAW/NO_BOQ/FAIL` → 收尾 `DONE ok=.. skip=.. scan=.. noboq=.. fail=.. skip_draw=..` + 清单。日志用**写模式截断**（不删，绕 safe-delete 钩子）。OCR 单页 ~5–20s，127 页扫描报价单约 20min/份，纯扫描报价单总数少、整体可控。

**全量质检 `qc_pdf_boq_v2.py`**（交付前必跑）：遍历产物六段锚点（`project_full_name`/`语义前置`/`分层明细`/`分项造价解读`/`汇总校验`/`检索索引`）齐备 + 语义前置 ≥120 字 + 明细表 ≥1 行 + **无千分位** (`(?<=\d),(?=\d{3}\b)`) → 出战报 `pdf_boq_qc_report.md` + 问题 `pdf_boq_qc_issues.csv`，按项目统计章节文件数与达标率。

> **塌块/漏章复盘（实战）**：首版靠页内"清单 第X章"标记切章 → 漏 100/500/800 且 700 章吞 600 章数据。**改为 `serial_from_code` 按子目号前缀推导章节后彻底修复**，且天然兼容跨页、缺章标题。质检须核对"六章齐全 + 每章行数合理"，否则漏章会静默漏网。

## 扩展4：批量驱动器（run_main_batch.py，跨数百文件断点续跑）

把整个投标 PDF+Excel 目录批量转 MD，按原目录条线镜像落盘（实战 360 文件 / 14GB / 10 标段验证）：

1. `os.walk` 源目录，收集 `.pdf/.xlsx/.xls`（可编辑 docx 按用户指令跳过）。
2. 路由：PDF → `clean_pipeline.py` + `to_markdown.py`；Excel → `excel_to_markdown.py`。
3. **目录镜像**：`outdir = OUT/相对源的子目录/<原名>.md`，保持与源相同目录结构（用户要求"按原目录条线"）。
4. **中间产物隔离**：cleaned TXT 存工作区，仅最终 MD 落目标盘，不污染目标盘。
5. **断点续跑**：目标 `.md` 已存在且非空则跳过（实战可中断后续跑，无重算）。
6. **日志**：`progress.log`（每行 `[时间] OK/FAIL <相对路径>`）+ 收尾 `完成 总计=N 成功=N 跳过=N 失败=N`；失败写 `fail.log`。
7. **后台与监控**：大批量 `run_in_background`；健康检查只看日志尾行时间戳 + OK 计数 + 待处理文件数，不要 sleep poll。
8. **规模估算**：PDF 大（271份/14GB，含 200MB+ 巨无霸）单份 10–30s，全量 1.5–3h；Excel 小巧（89份/0.19GB）秒级。
9. **全量质检脚本**（交付前必跑）：遍历产物统计 空文件数/HTML标签文件数/残留清洗标记(`[层级路径]`、`【结构化表格】`)/未脱敏身份证(18位)/未脱敏手机(11位)；并与源文件数交叉核对（实战 360=360 全绿）。注：桥梁技术参数 `<L≤140m` 这类数学写法会被 HTML 正则误报为标签，需肉眼排除。
