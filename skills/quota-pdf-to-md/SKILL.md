# 定额类 OCR PDF → 结构化 Markdown 知识库

适用：工程预算定额、消耗量定额等 PDF，文本层来自 OCR，带有**错位覆层**、含**定额表**（定额编号 + 人工/材料/机械资源消耗量）。

## 第一步：先诊断，别硬编码（最重要）
不要假设字体名/颜色可区分干净层。先跑 4 层诊断：
1. `get_text("dict")` 统计字体分布、是否有 CIDFont 乱码层（`encoding=="Identity-H"` 且无 cmap）。
2. 章节/节/定额编号分布（`\d+[-－]\d+[-－]\d+[-－]\d+` 4 段 or 3 段）、代号位数。
3. color / flags 是否能区分干净层（多数 OCR 覆层同色同字体 → **不能**）。
4. 覆层是每页 blocks 的头部还是尾部连续块？是内容信号型还是位置重叠型？

本类 PDF 典型特征：**无 CID 乱码，但有同字体同色的错位 OCR 覆层**，覆层恒为 blocks 的尾部后缀。

## 第二步：双层隔离（核心）
- 机制1 内容信号（`block_is_garbled`）：半角标点紧邻中文、字母替数字(O/g/l)、合并连字符编号(`53-7-56`)、半角数字邻全角句号(`5。池体防腐`)、与前面干净块长串(≥12字)逐字重复 → 命中即触发**后缀丢弃**（丢弃该块及其后所有块）。
- 机制2 位置重叠：后续块与已保留块同 y(±3)/同 x 重叠且相似度高(>0.7) → 丢弃覆层副本，优先保留 Bold/大字号。
- 全本扫描确认 0 残留乱码签名后再继续。

## 第三步：定额表重建（顶表头布局）
结构：定额编号在**表头顶部**(y=hy)，子目名/单位紧邻其下(y=hy+15~75)，资源数值行在最下方(y≥hy+90)。
- 按定额编号表头聚类为若干表。
- 子目名/单位：`hy < y ≤ hy+90` 且**严格对齐某列中心(Δ≤20)** 的文本（借此排除跨列居中的“组名”，如“改性环氧树脂防水防腐涂料”居中于两列之间 Δ≈35）。
- 数值行：`y > hy+90`，按 y 聚类为行，列中心归位；代号前缀判定类别（`99…`=机械，`0019…`=人工，其余=材料）。
- 单位 `m³`/`m²` 常被 OCR 拆成 `m`+`³` 两个 span → 把 `³`/`²` 也当单位后缀。
- 表头行(定额编号/定 额 编 号)位于 y=hy，表区间下界要包含 hy，否则会被当正文重复输出。

## 第四步：文档装配与目录/页眉去噪
- **跳过目录页**：一页内出现 `[-—_=]{3,}\s*\d+$`（标题------页码）行 >2 即判为目录，整页跳过（目录页无定额表）。
  - 坑：目录条目常被拼接成单行，章标题计数会漏判 → 必须靠页码尾缀行计数，不能靠 `^第X章` 计数。
- 标题清洗：去掉 `第一节挖土------6` 的页码尾缀。
- 章节去重：**全局 seen 集合**。章标题在多页内容页重复出现（页眉），用“与当前章比较”会失败（因为目录把所有章按序重放，使重复标题只匹配前一章）→ 必须用全局 seen 集合跳过已见标题，内容仍并入该章。
- 层级：`## 章` → `### 节/子目` → `#### 说明/工作内容/分节号` → 定额表。
- `[数据待核实]` 仅用于确实缺失的表头项，**绝不编造/推断**。

## 交付前验证清单
- 抽样逐行比对 PDF（重点：数值不错位、不遗漏、不四舍五入）。
- 统计 `[数据待核实]` 分布（理想 0）。
- 层级校验：章顺序正确、无幽灵章、无重复章标题。
- 残留目录页码尾缀 / 重复文本计数应为 0。
- OCR 缺失处标 `[数据待核实]`，不静默填充。

## 实战补充：上海市市政工程预算定额2016(OCR).pdf（同字体同坐标双图层特例）
该 PDF 与上面"尾部后缀覆层"模型**不同**：干净层与乱码/重复层**同为 SimSun、同坐标共存**（Δy 可小至 2），不能用 block 级后缀丢弃。已验证可用的方法（坐标级 span 去重，非 block 级）：

1. **坐标级双图层去重（收益最大）**：对每个 span，先标 `garble=含混淆字母{OoIlZzSsGgBbQD}且含数字/连字符`；再两两比对，同文本近距重复放宽到 `Δx≤10 且 Δy≤7` 直接丢弃副本（消除同码双行如 `34110101` 水 造成的无名行）。中文替换型乱码层（重叠同坐标、含半角数字/括号）丢弃含半角数字/括号的一方。
2. **数值列归位用"定额编号列中心 + 距离阈值"**：以定额编号 span 的 `x0` 为锚生成列中心；只有数字 `cx` 到最近列中心的 `dist≤thr`（`thr=max(40, 0.5*min(列间距))`）才视为真消耗量，否则归为名称内嵌数字（如水泥标号 `42.5`），避免误吞真实消耗值。`validate` 必须用同一套锚+阈值，否则会把 `42.5` 误判为遗漏。
3. **分组标题（`人/工/材/料/机/械`）残片**：OCR 把"材料/机械"拆成单字（`材/料/机/械`），有时还逐字重复（`材材/水水/机机`）。
   - 混合行中的纯分组字 span **跳过**（不污染资源名，如 `其他材料费 料`→`其他材料费`）。
   - 整行纯分组字 span 收集为 `name`，交给 `is_group_cand`（全字符属分组字集、无码/单位/值）→ `flush_pending_group` 去重相邻单字后拼成 `材料/机械` 作分隔行；拼不成完整组的孤立残片丢弃。
   - OCR 重复字折叠只对**汉字**做（`re.sub(r'([一-鿿])\1+', r'\1', name)`），**不要**用 `r'(.)\1+'`——会把 `4000` 折成 `40` 损坏数据。
4. **名称定位不要用 `cx < label_edge` 门限**：本 PDF 部分块名称位于定额编号列**右侧**（如 `综合人工（土建）` x116，编号 x65），位置门限会把真名误丢弃 → 数据区内非码/非值/非单位/非标签/非分组字的中文文本一律视为资源名称。
5. **碎片归并（防名称加倍 + 数值不丢）**：
   - `merge_frag` 片段名已是锚名子串则跳过（`粉煤灰粉煤灰`→`粉煤灰`）；`name_parts` 相邻重复 token 折叠（数字 token 不折）。
   - 数值碎片**逐列归位**：对 pending 缓冲里每个值，按"锚行该列空→填锚行，否则回退上一锚行，仍占用→作 `（附X）` 附注"分配（非 all-or-nothing），解决 `.1451` 被整片丢入名称的问题。所有无法归位的数值**作为附注保留，绝不静默丢弃**。

### 本例最终指标（参考基线）
- 416 个定额块；层级 16 册 / 50 章 / 0 节（节为源内容页确实无，非 bug）。
- `[数据待核实]` 269：其中 code 缺失 265（约 182 为 `其他材料费/其他机械费` 等本就无代号的汇总行，属真缺口）+ name 缺失 3（代号确无名 span）。
- 潜在遗漏 35 处：几乎全是 OCR 缺失前导零的小数（`.232`/`.85`）及冲突列值，均已作 `（附X）` 附注保留，非整值丢失。
- 验证脚本 `validate.py` 以定额编号列中心为锚 + 同款 `thr` 距离阈值，只校验贴近子目列中心的真消耗量。
