# 定额 PDF → 可计算知识库

## 适用范围

消耗量定额（概算/预算定额）与台班费用定额。结构特征：转置矩阵表（列=子目、行=人工/材料/机械台班消耗）、7 位代号、含基价与人工/材料/机械费小计。校验器**不是费率表的"算例反算"，而是基价闭环**。

与相邻技能分工：`fee-schedule-pdf-to-calc-kb` 管费率表 + 计算规则 → 机器可执行；`cn-gov-eng-pdf-vectorkb` 管 OCR 损坏的批复公文；本技能管**定额子目 → 机器可套用 + 基价可复算**。费率技能内的"定额类文档分支"只保留费率向要点，完整管线以本技能为准。

## 核心心智模型

1. **转置矩阵**：一张定额表 = 列方向是不同子目（1-1-1、1-1-2…），行方向是人工/材料/机械台班的消耗量。解析时把"行=工料机、列=子目"转置成"每条子目一条记录 `{code, name, unit, 人工, 材料[], 机械[], 金额项[], 基价}`"。
2. **基价闭环是自带的校验器**：基价 ≈ 人工×人工单价 + Σ材料×材料单价 + Σ台班×台班单价 + Σ金额项。三本定额互为校验：3831/3832 的材料单价来自 3832 附录四、机械台班单价来自 B06/3833。闭环通过即证明提取零差错。
3. **水印结构化删除**（同费率技能）：用 `/Artifact <</Subtype /Watermark>> BDC…EMC` 块正则切除，禁字符级剥离（会误删"运输""通航"等同形字）。

## 标准流程

### 第 0 步：探查
PyMuPDF 打开，`page_count`、`get_toc()`、抽样 `get_text()`。重点判断：是否上下册合并 PDF（页码重复风险）、是否含附录四材料单价表、水印是否为标准 Artifact 块。

### 第 1 步：去水印（先于一切提取）
```python
import pymupdf, re
doc = pymupdf.open(SRC)
pat = re.compile(rb'/Artifact\s*<</Subtype\s*/Watermark[^>]*>>\s*BDC.*?EMC\s*', re.S)
for pno in range(doc.page_count):
    for xref in doc[pno].get_contents():
        raw = doc.xref_stream(xref)
        if b"/Watermark" in raw:
            new, n = pat.subn(b"", raw)
            if n: doc.update_stream(xref, new)
doc.save(DST, garbage=4, deflate=True)
```
验证：重开干净 PDF 全文搜水印句应为 0 命中；与原始文本 diff 差值恰等于水印字符总量。若水印非 Artifact 块（用 ExtGState 透明度或直接绘制），先 dump 内容流看 BDC 标签结构再定正则。

### 第 2 步：表格线框提取
用 `page.find_tables()`（线框识别），存 `tables_raw.json`（含每个表的 bbox）。跨页表按 col_count + 表题合并。类别列用**包含匹配**，绝不做水印字符剥离。

### 第 3 步：dno 锚定（3832 实测页码体系彻底失效，关键）
- 优先用**表首格自带定额编号**（如 `1－1－1`，注意全角连字符 `－`，先 translate 半角）。
- 同页 bbox 上方最近的编号标题块（`get_text("blocks")` 比 y 坐标）。
- 续表**继承前一表**的 dno。
- **禁用印刷页码 lookup**：3832 上下册各自从第 1 页编号致重叠 + 分册内跳号（主格式为 em-dash `—7—`），页码完全不可靠。

### 第 4 步：解析转置矩阵
- 列=子目、行=工料机；按 `(dno, 子目序号)` 跨页合并。
- **kind 判定必须按单位列**：代号 80 开头但单位"元"→金额项（如 8099001 小型机具使用费、7801001/7901001/7903001）；单位"台班"→机械。误判机械则闭环全崩。
- **单位列错位清洗**：代号 80 开头且单位以"台班"结尾但形如"掘台班""机台班""台班台班"→多出的前缀字移回名称尾部，单位归"台班"。
- **括号消耗值 `(10.40)` = 不计价参考量**（总说明第十条外掺剂不计价印证）；`num_paren` 捕获 paren 标志，闭环求和对**全类别**排除括号值；不要按材料名 hack 排除（实测"排除 5003xxx+硅灰"净修复仅 5、误伤 1，得不偿失）。

### 第 5 步：页级查重（上下册合并 PDF 必做）
每页 `"".join(get_text().split())` 取 md5，比对上下册区间；命中重复段建 `DUP_RANGE` 跳过。3832 下册 pdf697~974 与上册 pdf392~678 **逐字重复收录**，不做则子目数翻倍。00 层声明"重复收录已去重"。

### 第 6 步：基价闭环校验
`基价 = 人工×人工单价(106.28) + Σ材料×材料单价(附录四) + Σ台班×台班单价(B06) + Σ金额项`
容差 `max(1元, 0.1%)`。输出 OK / BAD / UNVERIFIABLE / NOBASE 统计。
- UNVERIFIABLE：材料为实物量(m³/kg/t)且无单价表，正常，不算错。
- BAD 跨页碎片 <0.5% 标注"以原 PDF 为准"，不硬修。
- **回填升级**：拿到 3832 附录四（1261 条，人工 106.28 元/工日与 3831 互证）后重跑，3831 实测 OK 786→3743、UNVERIFIABLE 3072→17（仅 4003005 竹胶模板原书缺价、8024001/8024004 缺台班价）。

### 第 7 步：双口径 + 发射三层
- `quota_data.json` 同时存 `verify`（回填口径）+ `verify_strict`（严格口径：只用可独立验证项），并**断言 strict 精确复现回填前统计**（如 786/9/3072/18）以证明解析器未变。
- 发射：`00-索引与AI使用指南.md`、`01-总说明层.md`、`02-定额数据层`按章分册、`03-套用规则层.md`、`04-附录四单价层.md`（如有）、`quota_data.json`、`app4_data.json`、去水印 PDF。
- 数值发射**禁 float 默认 str**（`1e+06`、`1.35513e+06` 会印进表格），走格式化函数：整数输出 int 形式，小数 `%.5f` 去尾零。

### 第 8 步：端到端验收
独立重算 ≥5 个原文基价全对；子目组（code）无重复；MD↔JSON 条目一致；无科学计数法残留。

## 台班定额专项坑（B06/3833）

1. 左右半页分两表，按页内行序 zip；左半页 5 种列数版式(8/9/10/11/12)，规格列可能是纯数字(如"800")被误当折旧起点 → 用闭环差值最小反选 drop(0/1/2)。
2. `find_tables` 把整列压成含 `\n` 合并单元格 → `num()` 失败，须跳过含 `\n` 列。
3. 章归属**禁用页码区间**（偏移跳变），用代号前缀 8001~8025→13 类映射。
4. 闭环：基价 = 不变小计(折旧+检修+维护+安拆) + 可变小计。

- JTG/T 3833-2018 台班定额（123p，封面标 B06-03-2007）：972 子目基价闭环 972/972 全通过；13 类 972 子目与说明第二条独立吻合。
- JTG/T 3831-2018 概算定额（952p）：891 表→3885 子目七章归户；回填 3832 附录四后闭环 OK 3743/3885、UNVERIFIABLE 17；双口径（严格 786/9/3072/18）保全。
- JTG/T 3832-2018 预算定额（1483p）：1414 表→5017 子目 9 章；三级 dno 锚定 + 下册重复段(296页)哈希去重 + 单位列错位清洗；基价闭环 OK 4835(96.4%)；附录四 1261 条基期单价表为跨库枢纽资产。

## 交付红线

基价闭环为硬闸（不正则改数值凑通过）；歧义处标注"以原 PDF 为准"；不编造缺失类别；子目级索引供引用溯源；人工/材料/机械三类基价全链路闭环打通才算体系完成。

## 纯消耗量定额 + OCR 路线专项坑（SH00-41 修缮定额实战）

适用场景：PDF 文本层全乱码（WPS 私有 CID 子集字体，无 ToUnicode）→ 200dpi 渲染 + 本机默认引擎 `paddlevl-ocr` 精解通道（PaddleOCR-VL-1.6）全文 → 纯 OCR 解析。默认 `--engine auto` 探测到私用区乱码会自动选精解通道，无需手工指定。此类书为纯消耗量定额（无基价列），校验改四重：编号连续性 + 章说明子目数声明 + 代号字典一致性 + 工程量规则单位核对。

1. **单位行漏检修复（转置矩阵表头第三行）**：OCR 对小字号单位行（榀/樘/根/m²）整行漏检时，用 `get_drawings()` 矢量网格定位行带 → 400dpi 渲染各列格子 → 模板匹配回填。**坐标系陷阱**：OCR 中心是 px、网格线是 PDF pt，必须 ×72/200 换算，否则列定位全部失联（症状：assigns 恒为空）。
2. **匹配算法选型**：整格 IoU 对复合单位（m²）被 pad_square 纵横比失真压分（同形 'm' 仅 0.19）。采用**双路**：①膨胀(3×3,1次)合并断笔 → 连通域拆字 → 单字符模板逐字匹配 → 拼串 → 单位词表校验；②失败则整格 IoU 对整词模板兜底（单汉字断笔时可靠）。**必须用笔画粗细归一 IoU**（高斯模糊(9,9,σ3)+30%相对阈值二值化后比对），印刷细笔画与 SimSun 模板的粗细差会把同字 IoU 压到 0.17。
3. **两阶段早退 bug**：连通域路失败时禁止 `return None` 直接退出，必须落到整词兜底路（曾致"榀"全部漏配）。
4. **OCR 截断纠正**：OCR 常把 m² 捕成 'm'。回填策略：缺失→填；已有值是匹配结果的**前缀**（m→m2）→覆盖纠正；其余不一致仅强 margin(≥0.08) 覆盖。
5. **表头编号粘连定位**：多编号粘连在单个 OCR item（'20-3-1-1120-3-1-12'）时，若按 item 中心定位会使所有列中心塌缩成一点 → 消耗量/单位全错列。修法：在清洗文本内按序 `find` 各编号字符区间，按比例映射到 item 宽度。
6. **行带预筛**：候选行带内若 OCR 有数字 item（数据行）或 ≥4 字符文本 item（名称/说明行）→ 直接跳过渲染，只留单位行候选；取有效匹配列数 ≥ half 的带中最多者为单位行。
7. OCR 页号映射必须实测验证（本项目 pN.json ↔ doc[N] 0 基），勿凭 1/0 基假设。
8. **同页多表共享列网格时，编号去重必须按带隔离**（v4.4 关键坑）：全页以列中心 cx 为键去重会把第二张表的编号全部挡掉（两表共用网格，cx 相同）——症状是"缺号数恒等于 6 的倍数"（每漏一整行表头）。修法：out 改带内局部 dict，带间用 done_bands 防重复处理，各带结果 append 进全页 list（按 y 排序，下游按 y±25px 分组自然分表）。
9. **整带粘连大 box → 切列重读**：表头带 OCR 返回单个横跨全宽的大 box（'20132282018286...'）时 `_split_codes` 拆不出 → 该带全败。修法：带内仍有缺码列时按矢量网格列边界**逐列竖切**单独 OCR（col_ocr），单列宽图单列送入 `paddlevl-ocr` 能正确读出完整编号。**窄列编号图用 `--engine fast` 快速通道即可**，单页约 2 秒，比精解通道快两个数量级，且编号这类纯数字串正是快速通道的强项；整页表格与版面仍走精解通道。结果记 col_cache.json（键含列边界坐标）。
10. **折行序号行（第二行单个数字）det/rec 双失效 → 渲染图人工读码补丁**：两行式表头（第一行 '20-13-10-'、第二行 '4'）切列后 det 漏第二行、单字符 rec 返回空、resize 放大读出错误值（'4'→'41'）。此时唯一可靠路径：400dpi 渲染缺口带 PNG 人工读码，配合**结构四重验证**（矢量列数==序号数、cx 对齐、序号按列序连续、与前后已知编号衔接）后写补丁脚本重解析该页。residual 537→26 全靠此法。
11. **宽单列格带（列宽超上限）**：cols_spanning 列宽过滤上限（如 140pt）会滤掉单列表数据格（宽 ~286pt）→ cols 空被 continue 跳过。修法：cols 为空时回退"带内 OCR item 完整编号直接出码"（用 item 中心做 cx）。注意回退代码的去重集合必须**带内局部**，误用上带残留的全页 dict 会静默吞码。全书此类漏检一次扫出 26 个。
12. **纯数字代号被 clean_num 误吞（行级质量核心坑）**：8 位材料代号 13010101 是合法数字，clean_num 返回非 None → 被当消耗量数值、cx 离列远被丢弃 → code 空+cat 沿用 labor。症状：code 空率 85%、labor 占 96.7%。修法：数值判断**之前**拦截 `cx<660 且 fullmatch(\d{6,12}(\.\d+)?)` 建行；cat 按代号推断（FR=人工 JP/FC=材料 FJ/99*=机械 其余数字=材料，原书"材料/机械"类别字是竖排合并格 OCR 大多漏读，不可依赖）；无代号行按 unit 推断（台班→mach、kg/m³→mat、工日+X工→labor）。code 空率 85%→13.2%，剩余为原书代号列确实空白（渲染图核实）。
13. **反向审计适配（无基价定额）**：章声明对账（各章"共计N个子目"合计为锚）+ 编号连续性缺口分块状/零星/截断伪缺口三类 + **整节缺失检测**（某节首号>1 即整段漏，连续性审计不可见！ch13-12 曾漏 1..9 整段）+ 代号字典一致性（同代号多名称，OCR 同义变体 Φ/中、全半角括号为主）+ 同表同代号消耗量极差审计（>50 倍为疑点，实测 0 组）+ 渲染图人工抽验。
